# Privacy and data boundaries

RailRecover is designed around data minimisation and purpose limitation, but this prototype is not a GDPR compliance certification.

## Demo rules

- use synthetic names, descriptions, references and images only;
- do not enter passenger contact details, police references, ticket numbers or device identifiers;
- the browser demo stores fictional records in local storage;
- the Node demo stores fictional records in a local JSON directory;
- the public case study excludes direct and indirect identifiers where practical.

## Questions for professional review

Before real processing, an operator and privacy counsel must decide lawful basis, controller/processor roles, retention periods, access by organisation, passenger authentication, data-subject access/correction/deletion workflows, evidence-preservation rules, cross-border processing, breach response and publication review.

CCTV is out of scope unless an authorised integration, lawful basis, retention process and access controls exist. RailRecover should create a preservation request, not become an unauthorised surveillance viewer.
