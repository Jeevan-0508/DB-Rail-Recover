# Research & impact

RailRecover separates evidence classes so that a historical public reference is never presented as a current operational observation.

## Evidence classes

| Class | Meaning | Used in the demo |
| --- | --- | --- |
| Externally sourced | Published by a third party or operator; requires source/date/caveat | DB lost-property reference figures below |
| Synthetic demonstration data | Fictional cases, task responses and survey responses created for the app | Default dashboard state and scenarios |
| Hypothetical business-case assumptions | Adjustable planning inputs, not observed outcomes | Financial simulator |
| Operationally observed | Authorised pilot data with a defined collection protocol | None yet |

## Impact measurement boundary

The first authorised pilot should pre-register an analysis plan, define eligible cases, record baseline and intervention periods, preserve denominators, and report uncertainty. Recovery rate and passenger satisfaction are separate outcomes: a case can remain unresolved while communication is rated positively, or be recovered while the experience is rated poorly.
